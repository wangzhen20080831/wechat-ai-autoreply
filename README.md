# DeepSeek × 微信 自动回复

别人给你的微信发消息，DeepSeek 自动回。24 小时不需要你盯着。

拉下来跑一次 `setup.bat` 就装好了（虚拟环境、依赖、配置文件全自动）。
你要做的只剩两件事：**填一个 DeepSeek Key**、**决定让它回谁**。

---

以 MIT 许可开源（见 `LICENSE`）。

- 仓库里不放任何真实数据：示例中的人名、微信号、群名、路径全是占位符。

  触发策略、记忆、通知材料库、隐私闸门、失败补回。
- 你自己的 `.env`（DeepSeek Key）、`config.json`（白名单、会话 id）和 `data/`
  已经被 `.gitignore` 排除，不要去掉这几条。

## 先说三件必须知道的事

**1. 这是非官方接口，有封号风险。**
微信官方没有给个人号开放任何自动收发消息的接口。本项目走的是"读微信本地数据库 + 模拟人操作窗口"，
不注入、不 Hook、不破解协议，风险比内存注入类工具低，但**不等于没有风险**。
强烈建议：**先用小号试**，跑一周稳了再考虑上主号；行为保持克制（默认配置已经做了限速和冷却）。

**2. 发送消息时会短暂抢占你的键鼠。**
发消息靠"激活微信窗口 → 剪贴板粘贴 → 回车"。每次发送的零点几秒里，微信会跳到前台，
你的剪贴板会被临时占用、鼠标会被挪动一下。
如果你要 24 小时挂着，**最好的做法是拿一台专门挂机的电脑或虚拟机**，
而不是你天天用的主力机——否则你正打字的时候它可能突然抢一下焦点。

**3. 桌面不能锁屏，微信窗口不能被关掉或最小化到托盘。**
窗口不可见时 UI 自动化就找不到它。挂机电脑要把"自动锁屏"关掉。

## 三种方案的取舍

| | 本方案（个人微信） | 微信 Hook 类工具 | 微信客服（企业微信官方） |
|---|---|---|---|
| 能回好友私聊 | ✅ | ✅ | ❌ 只能回客服入口进来的人 |
| 需要降级微信 | ❌ 不用（支持 4.1.x） | ✅ 要降到 3.9.12.51 | ❌ |
| 封号风险 | 中低 | 高 | 无（官方接口） |
| 稳定性 | 中（怕 UI 改版） | 中 | 高 |
| 需要 | 一台常开 Windows | 同左 | 企业微信主体 + 服务器 |

**如果你是要给自己的私人好友自动回复**，本方案是当前最实际的选择。
**如果你是在做生意、要给客户做客服**，正经路子是注册企业微信、开通「微信客服」
（客户从客服入口进来，官方 API 收发，零封号风险，有 48 小时会话窗口限制）。
那条路要换一套代码，但更值得长期投入。

## 它是怎么工作的

```
别人发微信
    │
    ▼
[ 读微信本地加密数据库 ]  ← 每 1 秒扫一次新消息，不注入、不 Hook
    │
    ▼
[ 触发策略 ]             ← 白名单？群聊是不是 @ 到我（读微信记的 @ 名单）？
    │                       免打扰？冷却中？非文本？ 不合格就直接丢掉
    │
    ▼
[ 合并连发 + 随机延迟 ]   ← 对方连发 3 条，合成一次请求；等 3~8 秒再回，像真人
    │
    ▼
[ DeepSeek ]             ← 带上人设 + 这个会话最近 12 轮上下文
    │
    ▼
[ 清洗输出 ]             ← 去掉 markdown、引号、超长截断
    │
    ▼
[ 模拟人操作窗口发送 ]    ← 搜索会话 → 粘贴 → 回车
```

## 五步跑起来

### 第 1 步：确认环境（已经帮你装好了）

双击 **`setup.bat`**——只会做一次，创建 `.venv`、装依赖、生成 `config.json` 和 `.env`。
如果 `.venv` 已经存在，它会跳过。

### 第 2 步：填 DeepSeek Key

用记事本打开 **`.env`**，把这一行换成你自己的 Key：

```
DEEPSEEK_API_KEY=sk-你的真实Key
```

Key 在这里申请（充 10 块钱够用很久）：<https://platform.deepseek.com/api_keys>

### 第 3 步：自检

双击 **`doctor.bat`**。它会依次检查 Python 位数、依赖、配置、Key 能不能真的调通、
微信有没有登录、能不能读到数据库，最后告诉你还差什么。

```
✅ Python 位数 = 64 位
✅ wechatauto-replica 已安装（1.2.6.1）
✅ DEEPSEEK_API_KEY 已填写
✅ 调用 DeepSeek 成功（deepseek-chat）
✅ 微信进程在运行
✅ 读取本地数据库成功
❌ 白名单为空 → 白名单为空时谁都不会回（这是故意的安全设计）
```

### 第 4 步：决定让它回谁

这一步最重要。先看看你有哪些会话：

```
run.bat --list-sessions
```

会列出每个会话的 username、未读、名称。然后编辑 `config.json`：

```json
"trigger": {
    "mode": "whitelist",
    "whitelist": ["张三", "李四"],
    "groups": "at",
    ...
}
```

**白名单写的是微信里显示的名字**（备注名优先）。加进白名单的人，私聊才会被自动回复；
不在名单里的，一条都不会回。

`groups` 决定群聊怎么办：

| 值 | 行为 |
|---|---|
| `ignore` | 群聊完全不回（最保守） |
| `at` | **只有被 @ 到我 才回**，@所有人 不算（当前用的就是这个） |
| `all` | 群里所有消息都回（不建议） |

`at` 模式下，群里要同时满足两个条件才会回：**被 @ 到我** + **发消息的人在 `whitelist` 里**。
也就是说：白名单里的人 @ 你，会回；白名单外的群成员 @ 你，默认不回——想让他们也回，
把人名补进 `whitelist`；想让某个群谁 @ 都回，把**群名**加进 `whitelist`。

### 第 5 步：先演练，再正式跑

```
run.bat --dry-run
```

真的监听、真的调 DeepSeek，但**不发送**，只把"本该发什么"打在屏幕上。
看几条觉得没问题，再双击 **`run.bat`** 正式运行。

不想碰微信、只想验证 Key 和人设：

```
run.bat --once "在吗"
```

> **第一次真正发消息时会有一次约 10 秒的"布局校准"**：程序要量一下你屏幕的缩放比例，
> 才能算准"搜索框"和"输入框"的位置。校准时微信窗口会被弹到前台，属正常现象，
> 结果会存下来，以后每次启动都直接复用。所以**第一次跑之前，请把微信窗口打开
> 并保持可见（不要最小化）**。

## 白名单维护：批量加人（`tools/sync_whitelist.py`）

手工往 `whitelist` 里抄名字很容易踩坑——白名单匹配的是**微信里实际的显示名**
（备注优先），而名单上的人名经常和微信里对不上。对不上的结果不是报错，
而是**静默不回**，你根本不会发现。

名单里总有几个人和微信里的显示名对不上，工具会自动修正。常见的四类（名字均为示例）：

| 名单上的名字 | 微信里的显示名 | 问题 |
|---|---|---|
| 张伟 | 张玮 | 字不同（伟 / 玮） |
| 李娜 | 🐟娜 | 没设备注，昵称带表情 |
| 赵静 | 赵靜 | 异体字 / 繁简不同 |
| 刘洋 | `wxid_xxxxxxxxxxxx` | 通讯录里有 **3 个**刘洋，改用 wxid 锁定这一个 |

还有一种不怎么像「错误」的：白名单里可能混进**你自己的另一个微信号**。它在名册上，
工具就照着加了；不会造成乱回，但你要知道这条指向的是你自己。这也顺带解释了
「群里 @ 到你另一个号的昵称，有时算 @ 你、有时不算」的由来，见下面那节。

所以配置里的表情昵称和 `wxid_...` 不是笔误，注释里写了原因。

以后名单变了、或者你改了谁的备注，重跑一次就行：

```
.venv\Scripts\python.exe tools\sync_whitelist.py 名册.json --group 班级群名          预览
.venv\Scripts\python.exe tools\sync_whitelist.py 名册.json --group 班级群名 --write  写回
```

名单支持 `.json`（取 `rows[].name`）或 `.txt`（一行一个名字）。
`--group` 用班级群成员来消歧和兜底，强烈建议带上；不带的话只会在全部联系人里精确匹配，
异体字和昵称就找不出来了。

> 提醒：白名单认的是**显示名**。如果你以后把某人的备注从「王芳」改成
> 「2601班-王芳」这类，这条就失效了（同样会静默不回）。重跑一次脚本可以自动修正，
> 或者你也可以直接把 wxid 写进白名单，wxid 不受备注影响。

## 一台机器上登过多个微信号

程序自己会把检测到的账号列出来：

| 账号目录 | 昵称 | 状态 |
|---|---|---|
| `wxid_aaaa..._8810` | 我的昵称 | 现在在用的这个 |
| `wxid_bbbb..._da93` | 另一个昵称 | 另一个号，在同一个群里 |
| `wxid_cccc..._76ca` | （更早的号） | 100 多天没动过 |

看当前会用哪个：

```
run.bat --account list
```

**默认规则**：程序用「最近活跃（最后登录过）的那个号」，也就是你现在登录的那个。
所以**换号以后重启一下程序就行**，不用改配置。

想锁死某一个号（避免它认错），在 `config.json` 里写：

```json
"wechat": { "account": "wxid_bbbb..._da93" }
```

或者临时用命令行：`run.bat --account wxid_bbbb..._da93`。
启动时如果发现「最近活跃的号」和「实际读的号」不是同一个，日志里会有一条 ⚠️ 警告。

**换号之后要做的两件事**（各一分钟）：

1. 跑 `doctor.bat` —— 它会打印当前读到的账号和名字，确认读的是不是你想的那个。
2. 重跑一次白名单对齐：

```
.venv\Scripts\python.exe tools\sync_whitelist.py 名册.json --group 班级群名
```

因为**白名单匹配的是「那个号里的显示名」**，两个号的通讯录是各自独立的：

| 会跟着走的东西 | 需要重新对齐的东西 |
|---|---|
| 群里 @ 判定（用当前账号的 wxid + 该群的群昵称，自动读） | 备注名（另一个号可能没给同学加备注，昵称也不一样） |
| 你的人设、延迟、冷却、免打扰配置 | 白名单里那些 `wxid_...`（wxid 是账号级的，换号后失效） |
| 记忆文件本身 | 另一个号得重新解一次数据库密钥（第一次启动会慢一点） |

「人名差不多」能不能回，取决于另一个号里同学的显示名。同名同备注 → 直接能用；
备注不一样 → 脚本会把对不上的人列出来，改一下备注或者把新显示名补进白名单就行。

> 群里 @ 到你**任何一个号**都算 @ 你：把另一个号的 wxid 填进 `trigger.extra_at_ids`
> 就行。这适合「两个号都在同一个群里」的情况，别人 @ 哪个都是找你。不想这样就把那个数组清空。

## 配置详解（`config.json`）

全部字段都有默认值，没写的就用默认。最常改的是这四块：

### 1. 人设 `persona`

决定 AI 说话像不像你。`{owner}` 会被换成 `owner_name`。

```json
"owner_name": "我",
"persona": "你是「{owner}」本人，正在用自己的微信和对方聊天。\n\n要求：\n1. 中文口语，短句..."
```

**想让回复更像你本人**：把你平时常说的口头禅、回复习惯写进去，例如
"经常说'嗯嗯''行''回头说'，不用敬语，从不发超过两句话"。

### 2. 回谁 `trigger`

| 字段 | 默认 | 说明 |
|---|---|---|
| `mode` | `whitelist` | `whitelist` 只回名单里的人；`all` 回所有私聊（**不推荐**） |
| `whitelist` | `[]` | 名单。**留空 = 谁都不回**（故意的，避免装完就乱回） |
| `blacklist` | `[]` | 名单里的永不回复，优先级高于白名单 |
| `groups` | `ignore` | `ignore` 群聊不回 / `at` 只在群里 @ 我时回（@所有人 不算）/ `all` 全回 |
| `at_names` | `[]` | 额外补充「别人 @ 你 时可能用的名字」。一般不用填：程序会自己读你的微信昵称和**每个群的群昵称** |
| `extra_at_ids` | `[]` | 额外当成「我」的 wxid。你自己有第二个微信号、也在同一个群里时，把它写进来（当前配置里就是这个用法） |
| `at_text_fallback` | `false` | 有人**手打**「@你的群昵称」而没从微信列表里选人时，微信不记 @ 名单，默认就不回；设成 `true` 就按正文里的 `@名字` 也回（代价：万一群里有人和你同名，可能替别人答话） |
| `require_prefix` | `""` | 填了 `"AI"` 就只在消息以 AI 开头时才回，其余当没看见 |
| `cooldown` | `5` | 同一个人 5 秒内只回一次，防止对方刷屏时 AI 跟着刷 |
| `ignore_keywords` | `["退订",...]` | 消息里出现这些词就不回 |
| `skip_acks` | `true` | 对方只是应一声（`行` / `ok` / `好的` / `谢谢` / `👍`）就不回。这种消息会记进它的记忆（知道对方应过了），只是不开口；带问号、带内容的一律照回 |
| `ack_words` | `[]` | 除了内置那批，还想额外略过哪些词（例如 `["妥妥的"]`） |
| `quiet_hours` | 关闭 | 免打扰时段，例如 `{"enabled": true, "start": "23:30", "end": "07:30"}`，支持跨零点 |

#### 群里「@ 我」是怎么认出来的

这一层里最容易出错，所以做得比看上去讲究：

1. **优先看微信自己记的 @ 名单。** 别人 @ 人时，微信会把「被 @ 到的 wxid」写进那条消息里，
   程序直接读这个名单，所以**重名也不会认错**。
2. **@所有人 / @全体成员 不算** @ 我，不会触发回复。
3. 只有极少数老消息读不到名单时，才退回「按名字猜」——那时认的名字是：
   `trigger.at_names` + 你的微信昵称 + **你在该群的群昵称**（群昵称是从微信通讯录里读的，
   每个群可能不一样，程序按群算）。

> 为什么必须读群昵称：微信里 @ 人用的是**群昵称**，不是微信昵称。你在群里的昵称可能和
> 微信昵称完全不同，别人 @ 你时正文写的是**群昵称**。不知道这一点，群 @ 就永远不响应。

### 3. 回复节奏 `reply`

| 字段 | 默认 | 说明 |
|---|---|---|
| `delay_min` / `delay_max` | 3 / 8 | 收到消息后等 3~8 秒随机时间再回，模拟真人打字 |
| `batch_window` | 2.5 | 对方连发消息时的合并窗口，窗口内不断刷新计时 |
| `max_reply_chars` | 300 | 单条回复最长字数，超了会在句末截断 |

`delay` 别调太小。秒回是机器人最明显的特征，也是风控最容易抓的特征。

### 4. 记忆 `memory`

| 字段 | 默认 | 说明 |
|---|---|---|
| `max_turns` | 12 | 每个会话记住最近 12 轮对话，更早的丢掉 |
| `ttl_hours` | 72 | 超过 72 小时没聊过，这段记忆自动清空（避免半个月后突然接旧话题） |

每个会话的记忆完全独立，A 的上下文不会串到 B 那儿去。

### 5. 通知材料库 `knowledge`

同学问「体测几点在哪儿集合」「医保怎么交」「教材什么时候领」，光靠模型自己发挥，
它迟早给你编一个时间出来。材料库就是治这个的：把通知文件读成文本存起来，
有人问的时候只把最相关的几段**原文**塞给模型，让它照着说。

**材料从哪来**

| 来源 | 说明 |
|---|---|
| 项目里的 `knowledge\` 目录 | 你自己往里丢文件。最干净、优先级最高。 |
| 微信收到的文件 | `%USERPROFILE%\xwechat_files\<账号>\msg\file\<年-月>\` 里的文件自动收录 |

支持 `docx` / `pdf` / `xlsx` / `txt` / `md` / `csv`，以及图片（`jpg` / `png` / `bmp` / `webp`）。

**打印出来再拍照 / 扫描的 PDF、以及同学拍给你的通知照片，会自动认成文字**，
不用你自己再敲一遍 —— 见下一小节。

**扫描件和照片会自动转成文字（OCR）**

打印出来盖了章、再拍照或扫描成 PDF 的通知里**没有文字层**，普通解析只能读出空气。
程序会把这种 PDF 渲染成图片，用 **Windows 自带的 OCR** 认成文字（离线、免费、
不用装 Tesseract）；`knowledge\` 和微信里的**图片**也走同一条路。

| 参数 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关。关掉就退回老行为：扫描件和图片直接跳过 |
| `lang` | 空 | 留空自动挑，优先简体中文；一般不用填 |
| `dpi` | 300 | 渲染分辨率。中文 OCR 要 300；调低更快，但更容易认错字 |
| `max_pages` | 10 | 一份文件最多认几页（防着几百页的扫描书） |
| `max_chars` | 3000 | 认够这么多字就停，后面的页不看了 |
| `trigger_chars` | 60 | 文字层少于这个字数才试 OCR —— 正常 PDF 不会白跑一遍 |

认出来的文字照样**要过一遍隐私闸门**才入库。实测有三份以前读不出的扫描件
（开放活动安排表、反诈宣传通知等）这轮进了库、也能搜到；另外两份恶搞文件
（一个西瓜照片、一个表情包）认不出字，被正确地丢掉了 —— 文件名写着「通知」
不代表里面真有通知。

> 想快一点跑一次索引、先不管扫描件：
> `.venv\Scripts\python.exe tools\index_notices.py --no-ocr`

**隐私闸门（这一步千万别关）**

文件抽完文本先扫一遍，四条规则：

| 规则 | 为什么 |
|---|---|
| 含**身份证号** | 一个都不放过 |
| 含 **5 个以上手机号** | 一两个是通知里的咨询电话，几十个就是名单 |
| 含 **20 处以上「学号」一类的长编号** | 学费账单库、考生名单这种，一篇就是几万人 |
| 文件名像**花名册**（名单/名册/汇总表/统计表/信息表/摸底/座位表…） | 只拦微信自动收集的；你自己丢进 `knowledge\` 的不管 |

一次真实的首次索引大致是这样：扫 200 多份文件，入库的只剩三分之一，其余是这么被挡在外面的——
迎新资料/学生作业、重复副本、文件名像花名册、含身份证号、含一批手机号、
学号名单、认不出字的图片/扫描件、单文件太大。

被挡下最该挡的那一批长这样：`某班-学生基础信息表`（几十个身份证号）、
`学生信息一览`（上千个）、`某学院宿舍信息`（上千个手机号），
还有一份几百万字的**全学院学费账单库**（几万人的姓名、学号和欠费金额）。
这种文件一旦进库，同学问「我学费交了吗」，AI 会一本正经地从里面翻出来念。

**代价要说清楚**：助学金、助学贷款那类申请表本身就带身份证号，会被一起拦下。
所以问「助学贷款怎么申请」它答不上来，只会说「我确认一下再回你」。
想让它能答，把通知正文（不带名单的那一段）摘成 txt 丢进 `knowledge\`。

**还有一批「不是通知」的文件**：微信缓存里混着迎新资料包（学长学姐写的
《大学科普常识》《宿舍生存指南》之类）和同学的项目作业文档。这些默认按文件名
排掉了（`exclude_keywords`）—— 它们不是学校的通知，答同学问只会添乱。
想收回哪个，把 `config.json` 里对应的词删掉，再跑一次 `run.bat --index`。

**怎么用**

```
run.bat --index                       建/更新索引，建完就退出，不监听
run.bat --index --reindex             忽略缓存，全部重读一遍

.venv\Scripts\python.exe tools\index_notices.py --list          看库里有什么材料
.venv\Scripts\python.exe tools\index_notices.py --search 体测    只用本地检索试一句
.venv\Scripts\python.exe tools\index_notices.py --no-wechat     只索引 knowledge\ 目录
.venv\Scripts\python.exe tools\index_notices.py --no-ocr        先不 OCR 扫描件（快）
```

`--search` 是最该常用的一个：同学问的东西五花八门，先自己搜一下，看通知里到底有没有能答的。
搜不到就说明该补文件，或者干脆别让 AI 硬答。它**不联网、不花钱**。

**参数**

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 关掉就完全不读文件，一切照旧 |
| `dirs` | `["knowledge"]` | 本地放材料的目录 |
| `wechat_files` | true | 是否连微信收到的文件一起收录 |
| `auto_index` | true | 每次启动自动扫一遍新文件（只处理新增和改过的） |
| `max_chunks` | 4 | 每次塞给模型几段原文（多了费 token） |
| `max_chars` | 2000 | 原文总长度上限 |
| `recent` | 5 | 另外附一份「最近的通知」标题清单 |
| `ocr` | 全开 | 扫描件/照片自动转文字，参数见上面那一小节 |
| `exclude_keywords` | 一批 | 按文件名排除。默认排掉迎新资料包和学生作业，删词就能收回来 |

规范做法是：把真正要紧的通知丢进 `knowledge\`，把 `wechat_files` 当成兜底。
同一个通知常被转发好几份，内容一样只留一份（自动去重）。
库越干净，答得越准 —— 删词比加词安全，所以拿不准就先留着。

## 和另一个 Codex 会话共享班级记忆（`sync`）

如果你还开着一个「班长助理」的 Codex 会话（负责盯负责人群、把通知要点和草稿给你），
那它和这个机器人原本是两套记忆：机器人知道同学问了什么，会话知道班级事务的来龙去脉，
互不相通。开 `sync` 之后两边共用一个目录，各写各的那一半：

| 文件 | 谁写 | 谁读 | 内容 |
|---|---|---|---|
| `dialog.jsonl` | 机器人 | 会话（机器可读） | 每条问答一行 JSON |
| `dialog.md` | 机器人 | **会话每次运行先读这个** | 「谁 + 问了什么 + 机器人怎么答的」 |
| `bot-status.md` | 机器人 | 会话 | 最后同步时间、累计条数、进程号 |
| `knowledge.md` | **会话** | 机器人 | 班级记忆正文：群清单、通知进展、谁负责什么、口径 |
| `inbox\*.md` | **会话** | 机器人 | 随时追加的补充记忆，接在 `knowledge.md` 后面 |

配置长这样（`dir` 写成两边都能看到的绝对路径）：

```json
"sync": {
  "enabled": true,
  "dir": "D:\\bot\\shared-memory",
  "max_chars": 4000,
  "dialog_keep": 200,
  "refresh_seconds": 15
}
```

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` / `dir` | 关 / 空 | 两个都填了才启用。`dir` 相对路径按项目根算 |
| `max_chars` | 4000 | 每次塞进提示词的共享记忆上限（超了截断） |
| `dialog_keep` | 200 | `dialog.md` 里保留最近多少条对话 |
| `refresh_seconds` | 15 | 后台每隔多少秒对一次表；`0` = 只在回复时同步 |
| `session_read` / `session_thread` | 关 / 空 | 直接读那个会话的记忆：填上它的 thread id 才生效 |
| `session_items` | 12 | 取它最近多少条对话 |
| `session_max_chars` | 3000 | 这段会话记忆的字数上限 |
| `session_tail_mb` | 3 | 第一次只读记录文件尾部多少 MB（那文件可能几十 MB，不整份读） |
| `session_skip_user` | 空 | 额外要当作「自动注入、不算班长说的」前缀，一行一个 |

**会话那边不用动手写文件，机器人也能读到它。** 上面那张表说的是「会话主动写、机器人读」；
除此之外机器人还会**直接读那个 Codex 会话自己的对话记录**：`%USERPROFILE%\.codex\sessions`
里它的 rollout 文件，按字节增量捞出「我（班长）说了什么 + 会话最后回了什么」当作班级记忆。
所以会话里刚聊完的事（值日怎么排、某个通知处理到哪一步、谁负责什么），机器人几秒后就能用上，
既不用会话动手写文件，也不用等它的定时任务。开关就是下面 `session_*` 那几项。

**「实时」到什么程度。** 机器人这边是真实时：每条消息回复前都会重看一眼（只看文件大小、
修改时间，以及记录文件新增的那几个字节，很便宜），任何一边一改，下一条回复立刻用上，
**不用重启机器人**。只有「机器人 → 会话」这个方向做不到实时：Codex 会话不会被人叫醒，
它每次运行（默认每天 4 次）先读 `dialog.md` —— 想让会话马上看到最新的对话，
在会话里说一句「读一下 shared-memory」。

**隐私闸门照旧，而且更严。** 从共享目录读进来的内容要过一遍检查，成规模的名册
（身份证号、成片的手机号/学号）**整份拦下不进口**。直接读会话记录时还要多一道：
会话汇报里出现的身份证号、手机号、长号码会被**就地抹成「（身份证号已隐去）」这类占位符**，
整条名册才丢掉 —— 会话的汇报里真的出现过同学的身份证号。`data\bot.log` 里会写明
这一轮脱敏了几条、丢了几条。

手工对一次表（不连微信、不发送，随时可以跑）：

```
run.bat --sync              推新对话出去 + 读回班级记忆，打印结果
run.bat --sync --reindex    清掉已同步的对话记录，从头重新生成
```

## 24 小时挂机要处理的几件事

**关掉自动锁屏和睡眠。** 设置 → 系统 → 电源和睡眠 → 屏幕改成"从不"，睡眠改成"从不"。
锁屏后 UI 自动化就失效了，消息会攒着不回。

**微信不要关、不要最小化到托盘。** 可以最小化到任务栏，但不能退出。
挂机机器上可以把微信窗口挪到屏幕角落或另一个虚拟桌面。

**开机自启。** 按 `Win+R` 输入 `shell:startup`，把 `run.bat` 的快捷方式丢进去。
或者用"任务计划程序"建一个"计算机启动时"触发的任务，程序填：

```
<项目目录>\.venv\Scripts\python.exe
```

参数填 `-X utf8 main.py`，起始位置填项目目录。

**桌面快捷方式。** 桌面上有个「DeepSeek 微信自动回复」的图标，双击就启动（最小化
跑在后台）。同一个机器人**只允许开一个**：重复双击时，第二个会弹窗提示"已经有一个
在跑了（PID xxx）"然后自己退出 —— 两个进程同时监听的话，同一条消息会被回复两遍。
要重启，先关掉那个最小化的黑窗口，再双击。

**看日志。** 所有动作都写在 `data\bot.log`：

```
10-14 18:31:02 INFO    [收到] 张三：明天那个会几点
10-14 18:31:07 INFO    [发出] 张三：下午两点，我提前十分钟叫你
```

日志里会清楚记录每条消息为什么被跳过（比如"不在白名单里"），排查特别方便。

**想暂停？** 直接关掉那个黑窗口就行。记忆存在 `data\memory.sqlite3`，重启接着用。

## 常见问题

**Q：它回了不该回的人怎么办？**
关掉程序，把那个人加进 `trigger.blacklist`，或者确认 `mode` 是 `whitelist` 且名单里没有他。
`blacklist` 优先级最高。

**Q：为什么 `run.bat` / `doctor.bat` 里面全是英文？**
因为批处理文件里**不能写中文**。cmd.exe 是按系统代码页（中文 Windows 是 GBK）
逐行解析 `.bat` 的，文件里的 UTF-8 中文会被切碎：行可能在英文单词中间断开，
连 `if ( … )` 块都会散架 —— 结果是脚本一声不响地什么都不做（这个坑真踩过：
机器人根本没启动）。所以 `.bat` 一律保持纯 ASCII，需要给用户看的中文提示
放在 `tools\msg\*.txt` 里，用 `type` 打出来。改这些脚本时请照做。

**Q：消息收到了但不回。**
看 `data\bot.log` 里那条"跳过"的原因。最常见的是：不在白名单、群聊被拦、非文本消息、
或者正好在冷却/免打扰时段。

**Q：机器人怎么和 Codex 那个「班长助理」会话共享记忆？**
见上面「和另一个 Codex 会话共享班级记忆」那一节。一句话：机器人把同学问答写进共享目录，
会话把班级知识写回 `knowledge.md`，机器人每条消息回复前重读一遍，改完立刻生效。
想手工对一次表：`run.bat --sync`。

**Q：群里 @ 了我，它却没回。**
按优先级查这四条（日志里会直接写原因）：

1. `群里没有 @ 我（微信的 @ 名单里没有我）` —— 那条 @ 是给**别人**的。
   群里可能有人和你的群昵称重名，你自己的第二个号也可能用同一个昵称，
   程序按微信记的 wxid 区分，所以有时正文写着 `@你的群昵称` 也不是给这个号的。
   如果你就是想让「@你的群昵称」都归当前这个号管，把 `trigger.extra_at_ids` 补上那个 wxid。
2. `群里是 @所有人，不是单独 @ 我` —— 设计如此，@所有人 不触发。
3. `不在白名单里` —— 发消息的人不在 `whitelist`。
4. `非文本消息` —— 图片/文件/表情不会被自动回（只回文本）。

还有一种情况日志上看着像「群里没有 @ 我」：对方**手打了** `@你的群昵称` 但没有从微信弹出的成员列表里
选人。这种「假 @」微信不记录 @ 名单，程序就不知道是给你。要连这种也回，把
`trigger.at_text_fallback` 改成 `true`。

**Q：@所有人 也会自动回吗？**
不会。@所有人 在微信里是 `notify@all`，程序能认出来并且明确跳过。

**Q：我换了微信（或者换成我另一个号），还能自动回吗？**
能，但要做两件事：重启程序（它会自动认最近登录的那个号）、重跑一次 `doctor.bat` 看账号对不对；
再重跑一次 `tools\sync_whitelist.py` 把白名单跟新号里的显示名对齐。详见上面的
「这台机器上有两个微信号」一节。

**Q：发送失败，日志说找不到会话。**
微信搜索框搜不到就发不出去。检查 `whitelist` 里的名字和微信里显示的**备注名**是不是完全一致
（包括空格、emoji）。跑 `run.bat --list-sessions` 看真实名字。

**Q：同一条回复对方收到了两遍。**
发送那条链路判断"发出去没有"靠的是界面状态（回车后输入框有没有清空），界面上偶发的一两次
误判会让它把同一段话再发一遍。默认 `wechat.verify = true`：发完回读微信数据库确认，
确认不到就等一会儿再判失败，**不会再重发**；数据库里已经能看到这条就直接算成功
（日志里会写一条"界面判定没发出去，但数据库回读确认已发出"）。代价是每条消息多花几秒。
真要图快可以把它改成 `false`，但界面那点误判就会重新变成重复消息。

**Q：我在微信里自己回了他，机器人还会跟着回吗？**
不会抢。机器人收到同学消息后要等 3~8 秒（装真人打字）才回，这几秒里你要是自己先回了，
它就把排队的那条撤掉，一个字都不补。生成慢的时候（DeepSeek 高峰可能要几十秒）也一样：
发出去之前它会再看一眼「你回来没有」，回来了就不发，连已经写进记忆的那句草稿都删掉
（日志里搜 `[不抢了]`、`[你自己回了]`）。

**你手动回的话也会记进它的记忆**（记成「我说过的话」），并同步进共享记忆 —— 不然它下次
开口还当对方的问题没人答过，会重复问、重复答。它只管白名单里的会话（群按 `trigger.groups`
算），你在别的私聊里说的话不会进记忆，也不会被同步出去。它自己刚发出去的那句会被监听读到，
那算回声，不会记两遍。

升级之前你自己回过的话它不知道，可以补一次（只读微信数据库，再写它的记忆库，重复跑不会重复插；
它自己发过的会被认出来，不会补成两条）：

```
.venv\Scripts\python.exe tools\backfill_self.py --all-watch --hours 12          先看今天你说过哪些
.venv\Scripts\python.exe tools\backfill_self.py --all-watch --hours 12 --write  补进记忆
.venv\Scripts\python.exe tools\backfill_self.py --conv 某人 --hours 24 --write 只补某一个人
```

**Q：对方只回「行」「ok」「好的」「谢谢」，它也回吗？**
不回（`trigger.skip_acks`，默认开）。单独一句应答就放着，不然对方说「行」它回「好嘞」，
像话痨，也更容易露馅。能叠着认：「嗯好的」「好的，谢谢」「行 谢谢」都算；只在群聊里
@ 了它也一样不回。但这句会**记进它的记忆**（知道对方已经应过了），下次开口不会又问一遍。

带问号、带疑问词（「行吗」「这样可以吗」「好的我这就去办」「谢谢班长，那报名时间呢」）
的一律照回 —— 拿不准的时候宁可回。日志里这类记成 `[只记不回]`；嫌它略过太多，
把 `trigger.skip_acks` 改成 `false` 就每条都回。

**Q：日志里出现「生成回复失败」，对方是不是就收不到回复了？**
不会。以前确实会丢（DeepSeek 一超时这条消息就没了，同学那边看起来就像被无视），现在不会：
生成失败的消息会立刻记成**待办**，写进记忆库（重启也不丢，一个会话只留一条），
20 秒后自动重来（最多 2 次），再不行就交给后台每 2 分钟接着试；同学这期间又说了新话，
会和欠着的那条**合成一次回复**，不会前一句后一句对不上。拖过 2 小时还补不上才会放弃，
并且日志里会写明「哪个人、哪句话到最后也没补回来」。

失败就两类：DeepSeek 高峰时段慢（原来 60 秒超时不够用，已把 `model.timeout` 提到 120 秒），
以及服务端 503「服务繁忙」。节奏参数都在 `config.json` 的 `reply` 段，随时可调：

```json
"retry_delay": 20.0,             // 失败后隔多久自动重来一次
"max_retries": 2,                // 这种「马上重来」最多几次，之后交给后台
"pending_flush_seconds": 120.0,  // 后台多久扫一遍待办
"pending_max_age_hours": 2.0     // 拖过这么久还补不上就放弃
```

日志里搜 `[补回]` 能看到整条补回过程（欠着 → 重投 → 补回成功 / 放弃），重启时也会把
上次没补回来的列出来。想知道现在欠着几条：

```
.venv\Scripts\python.exe tools\requeue.py
```

**Q：升级之前丢的那几条（当时程序还不会补）怎么办？**
那几条记忆库里没记录，程序不会自己去补。要是还想让它回，用 `tools\requeue.py` 排进去：

```
.venv\Scripts\python.exe tools\requeue.py                    看现在欠着谁
.venv\Scripts\python.exe tools\requeue.py --conv 某人 --text "在吗"        先预览
.venv\Scripts\python.exe tools\requeue.py --conv 某人 --text "在吗" --write 真排进去
.venv\Scripts\python.exe tools\requeue.py --conv 某人 --drop --write        不补了，撤掉
```

排进去之后，运行中的机器人会在 2 分钟内按正常流程回这一条（它当成刚收到的消息，
口吻不会带「拖了两小时」的痕迹）。**自己已经回过的消息就别排了**，否则对方会收到两条。
另外它没法回「10:05 提醒我下课」这种过时的事 —— 时间点已经过了，补不如不补。

**Q：同学问「体测几点在哪集合」，它答的是真的吗？**
只要那份通知进了库，它就是**照原文答**的：程序先按关键词把最相关的几段原文
（时间、地点、金额、截止日期都在里面）塞进提示词，人设里又写死了
「必须跟材料完全一致，材料里没有的就说我确认一下再回你」。
实测问「体测什么时候测、在哪集合」，能答出《华北理工大学2026年秋季国家学生体质健康标准学生测试通知》
里的东一体育场和 10 月 19 日。

前提是那份通知**进得了库** —— 见下一个问题。

**Q：为什么有的通知它就是答不上来？**
三种情况，索引报告和日志里都会写明原因：

1. **认不出字的图片**。扫描件和照片现在都会自动 OCR，但表情包、纯截图、拍糊了的照片
   认不出几个字，还是会被跳过（索引报告里会写明「OCR 只认出 N 字」）。另外 OCR 是
   「认字」，表格那种密密麻麻的排版有可能会认串行 —— 真正要紧的通知，
   把文字版丢进 `knowledge\` 最稳妥。
2. **带名单的表**。含身份证号、5 个以上手机号、或一堆学号的文件会被隐私闸门拦下 ——
   助学金申请表、贫困生档案库、学生信息表、宿舍摸底表、学费账单库都在这一类。
   这是故意的：进了库，同学问「某某的身份证号是多少」，它会照着念。
3. **微信里没有的文件**。库里只收你微信收过/发过的文件。别人手机上的通知，它看不到。

想事先确认某个问题能不能答上来，拿同学的原话试一句最直接：

```
.venv\Scripts\python.exe tools\index_notices.py --search 体测在哪儿集合
```

**Q：它还记不记得之前的对话？**
记得，而且是**按人分开记**的：每个会话单独存最近 12 轮（`memory.max_turns`），
超过 72 小时没聊就自动清空。通知材料是另一套（`knowledge`），它是"长期记忆"——
不影响对话历史，每次提问都按你问的内容去库里现查。

**Q：Key 明明对，doctor 却说鉴权失败。**
确认 `.env` 里没有多余引号、没有中文空格；确认账户有余额（DeepSeek 是预充值）。
如果公司网络有代理，设 `HTTPS_PROXY` 环境变量。

**Q：一直提示数据库密钥读取失败。**
退出微信客户端，重新登录，再跑一次。密钥是登录后从进程内存里读的，微信没登录就读不到。

**Q：会不会把消息发串到别人那儿？**
发送前会通过微信搜索框精确定位会话，只往目标会话发。但要额外提醒：
**发送过程中别去抢鼠标**，人工介入可能干扰定位。所以挂机机器别同时干别的。

**Q：DeepSeek 一个月大概多少钱？**
按 100 条/天、每条来回约 300 token 算，一个月约 90 万 token。
DeepSeek 是全网最便宜的级别，这个量一个月几块钱。缓存命中的话更便宜。

## 让它更安全的几条建议

- **跑之前先想清楚**：这是你的私人微信，任何自动化都不该让你措手不及。先用小号，先只加一两个人，先跑 `--dry-run`。
- **别给 AI 太大的话事权**：`persona` 里已经写死了"涉及钱、验证码、银行卡、合同一律不给承诺"。这些别删。
- **别用它做营销群发**：高频、群发、加好友，这三件事是封号高危区，本项目的默认配置全都不支持。
- **回复延迟别关**：3~8 秒的延迟是保护你账号的，不是性能问题。
- **定期看日志**：花两分钟翻一眼 `data\bot.log`，能提前发现"它开始胡说"或"它回错人"这类问题。
